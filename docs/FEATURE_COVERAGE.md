# 功能对应与性能边界

本表记录扩展的功能入口和实现方式。BiliTube 重排常用浏览页面，复杂业务保留 Bilibili 原生组件。原生入口可补足管理和细分筛选能力；它们不代表扩展已经重新实现这些业务。

| Bilibili 功能 | 对应入口 | 实现方式 |
| --- | --- | --- |
| 推荐、分类、关注视频、直播、番剧、热门 | 首页分类与内容 Shelf | 扩展卡片与分页 |
| 综合、视频、用户、番剧、影视搜索 | 搜索结果上方分类 | 扩展结果列表 |
| 视频排序与时长筛选 | 视频搜索分类下方两排筛选 | URL、请求参数和缓存区分筛选条件 |
| 直播与专栏搜索 | 搜索分类中的“直播”“专栏” | 原生搜索页面与统一导航 |
| 分区、排行榜、国创、电影、电视剧、综艺、纪录片、课堂 | 侧栏“全部分区与服务” | 原生页面链接，不提前请求页面数据 |
| 创作中心、投稿 | 侧栏“全部分区与服务” | 原生创作页面 |
| 私信、通知、大会员、个人空间 | 顶栏与侧栏 | 原生业务页面或空间浏览页 |
| 视频播放、弹幕、画质、倍速、分 P、播放模式 | 播放页原生播放器 | 原生组件保留在原父节点 |
| 点赞、投币、收藏、分享、三连、充电、评论与回复 | 播放页原生工具栏与评论区 | 原生业务与弹窗 |
| 动态视频、文字、图片 | 动态列表 | 扩展列表；时间、图片及“查看动态与讨论”打开原生详情 |
| 动态评论、转发、点赞 | 动态详情 | 原生组件 |
| 发布动态 | 动态页右上方“发布动态” | 打开原生动态页面后发布 |
| 历史搜索、单条删除、清空和暂停记录 | 侧栏“历史记录” | 原生历史页 |
| 稍后再看添加与移除 | 卡片快捷按钮、稍后再看列表“移除” | 接口操作与列表同步，失败保留状态并提示 |
| 稍后再看播放全部、清理与其他管理 | 列表左侧“播放全部”、右上方管理入口 | 原生队列和管理页面 |
| 收藏夹浏览、播放全部 | 收藏夹列表与摘要 | 扩展分页与原生播放列表 |
| 收藏夹创建、编辑、删除、批量管理 | 收藏夹右上方“管理收藏夹” | 原生收藏管理 |
| 订阅收藏夹、搜索细分分区与发布时间等未覆盖条件 | 原有 URL | 保留原生页面与条件 |
| 其他原页面功能 | 替换页面右上方“打开 B站原页面” | 保留当前查询参数和锚点，单页恢复原界面 |

## 性能约束

- 首页、搜索、收藏夹和投稿分页只构建新条目的 DOM；原卡片、焦点、侧栏展开状态和已有预览绑定保持不变。数据替换、筛选切换或布局变化仍完整渲染。
- 分页请求开始时只更新底部加载提示。同页动态与异步资料更新构建暂存内容后按键更新已有 DOM，保留卡片和媒体；暂存封面只在实际采用后加载。
- 每个列表达到至少 300 条已加载条目后停止自动分页，改用“加载更多”。单次分页可能使总量略超过 300；手动继续加载仍会增加内存和 DOM 数量。
- 后台响应缓存与通用缓存各限制为 256 项，缩略图完成状态限制为 1,024 项，预览地址限制为 64 项并在两分钟后重新读取。缓存按项数限制，不是按字节限制。
- 缓存清空或条目失效后，未完成的旧请求不能重新写回失效数据；失败响应不长期占用后台缓存。
- 路由改变时清理请求序号和分页 observer。完整路由替换前释放旧预览绑定；同页更新只清理已移除卡片的预览，只有新增或媒体已变化的卡片重新绑定。
- 非可见卡片使用浏览器 `content-visibility`，缩略图保持懒加载；只有一个悬停预览会播放。
- 快捷入口不新增持续轮询。登录后稍后再看状态共用一次列表读取，避免逐卡片请求。
- 初次加载先显示占位，再显示 API 内容；原站卡片仅在接口失败时兜底。同一页面自动添加的追踪参数不会使已经显示的内容重新挂载。

这些约束控制扩展自身的工作量，无法保证 Bilibili 网络请求、原生播放器或任意设备上的固定帧率。

## 验证

```powershell
node --test tests/*.test.js
node scripts/verify.mjs
python scripts/feature_parity_smoke.py --help
python scripts/feature_parity_smoke.py
git diff --check
```

浏览器脚本需要 Python Playwright 和本地 Edge，可通过 `--browser` 指定其他 Chromium 浏览器。输出保存在忽略提交的 `output/feature-parity/`。脚本使用隔离 API 数据，覆盖筛选导航、分页节点保留、自动分页上限、动态详情、稍后再看移除，以及 1,000 条已有卡片追加 42 条的 DOM 构建测量。测量不包含图片下载、布局、绘制或原生播放器耗时。

本轮另使用临时 Edge 配置加载实际扩展，在未登录的 Bilibili 视频搜索页读取到 42 条真实结果，排序与时长条件正确显示。动态详情只在隔离数据中验证；未登录的实时详情探测被站点重定向到 404。登录后的发布、评论、投币、收藏和队列写入仍需真实账号验收。

## 媒体连续性与主题切换验证

`python scripts/media_continuity_smoke.py` 使用真实 SVG 图片和本地 WebM 视频、隔离 API 数据，验证延迟资料更新、图片节点身份、视频播放进度和 `loadstart` 次数。还覆盖首页跨网格移动、普通播放页追踪参数变化、设置存储通知、快速反向切换和减少动态效果。需要 Python Playwright、Edge 和 FFmpeg；输出在 `output/media-continuity/`。

主题切换使用浏览器 View Transition API 的整页快照，仅改变旧快照的透明度，约 180 毫秒结束。移除全屏圆形裁剪，也不逐项动画修改页面颜色。浏览器不支持、系统要求减少动效或扩展设置关闭动效时直接应用主题。快照不移动或替换原生播放器。

实际加载扩展的未登录 Bilibili 搜索页用于主题帧间隔探测；隔离浏览器覆盖深浅两个方向、快速反向切换和媒体节点保留。公开页面检查不能代替登录后的账号业务验收。

`python scripts/watch_startup_probe.py` 对比同一公开视频的原生与扩展启动过程，记录 `loadstart`、播放器节点、媒体源设置与尺寸变化。源码修复前，扩展提前插入作者镜像会干扰原站 Vue 对 SSR 容器的初始化，触发 `Player.disconnect()` 与第二个视频节点。现在桥接 MAIN-world 的初始化完成状态后再插入作者行；`BV1GJ411x7h7` 和 `BV1xx411c79H` 两个未登录公开视频均记录到一次 `loadstart`、一个视频节点及正常作者镜像。

`python scripts/theme_performance_probe.py` 在 1920×1080、2 倍缩放的临时 Edge 环境记录 RAF 帧间隔和 Chrome Paint 轨迹。报告包含快照准备阶段的最长间隔，不能用整体中位数掩盖启动停顿；这些数据不是用户显示器的实际刷新率。脚本输出均保存在 `output/`，不提交账号或媒体 URL 查询令牌。

2026-10-26 在 Edge 156.0.4314.42 无头模式的三次探测中，请求至过渡结束为 222–250ms，RAF 帧间隔 P95 约 7ms，最长间隔 27.9–34.8ms。Paint 统计限定在切换请求与完成之间，等待 Chrome 的 trace 完整写出后才开始下一轮。这验证了当前浏览器中的短过渡路径，不作为有界面显示的帧率承诺。

`python scripts/watch_layout_smoke.py` 在 390、1000、1440、1920px 窗口验证预绘、挂载和延迟初始化三个阶段。四种隔离布局的播放器、标题、工具栏和简介几何一致，布局偏移为 0；另验证 6 秒超时恢复原生作者后，迟到的初始化不会再移动推荐列表。输出在 `output/watch-layout/`。

真实播放页探测增加逐帧区域几何与 Layout Shift 来源记录。修复前，`BV1GJ411x7h7` 的播放器从 y=174 移到 72，工具栏在作者到达时下移 40px；修复后，这些外层区域的位置从首帧保持一致。原生播放器内部的弹幕、提示和互动控件仍可能产生自己的布局变化，不能将隔离布局的 0 偏移推广为整个生产页面的 0 偏移。

2026-10-26 的同页原生/扩展对照均出现站点 `COLS: response timeout`，均只有一次媒体 `loadstart` 且最终处于播放状态。该次检查确认外层布局和播放连续性，不表示生产页面没有站点脚本错误；原始记录位于 `output/watch-startup-control/report.json`。

2026-10-26 使用 `scripts/watch_navigation_probe.py` 在临时未登录 Edge 156.0.4314.42 中点击真实右侧推荐，复现播放器容器丢失布局标记：从 `BV1cU4y1A7ud` 进入 `BV11t411y7FV` 后，播放器仍在播放，但 flex order 变为 6、顶部落到 y=1114.5，首屏只剩标题和评论。补齐播放器容器 class 监听后，同一路径及随后共 5 次同页推荐切换均保持播放器在 y=72、标题上方；各次媒体 readyState=4、处于播放状态，全程未刷新。对照记录分别在 `output/watch-navigation-before/` 和 `output/watch-navigation-after/`。这覆盖公开推荐导航，未使用用户登录配置。
